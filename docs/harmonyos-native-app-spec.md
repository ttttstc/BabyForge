# BabyForge 鸿蒙原生内测版实施规格

状态：最终实施规格；全部原型页面与跨端同源约束已确认，可进入拆票  
目标版本：HarmonyOS 原生内测版  
设计结论：采用已验证原型 B“定稿组合”  
代码基线：`codex/sync-main-20260817` / `a68f5a8`  
规格 Issue：GitHub #69  

## Problem Statement

BabyForge 已有 Web 客户端、真实账号与家庭数据、照护事件协议、确定性规则、审核内容和奶爸 AI 服务，但当前 HarmonyOS 研究版本仍不足以提供完整的系统原生手机体验。照护者需要在单手、低压力的手机场景中快速理解今天、记录已发生事实、查看宝宝照片、处理今日事项并与奶爸 AI 交互；如果继续把 Web 页面装入 ArkWeb 外壳，导航、表单、返回手势、键盘、加载、失败反馈、离线状态和系统能力都无法真正符合 HarmonyOS 使用习惯。

同时，原生化不能复制一套会与 Web 漂移的业务或医学安全逻辑，不能把未同步的本地输入伪装成正式照护事实，也不能让插画、AI 或参考 App 的视觉结构改变 BabyForge 已确认的事实语义与安全边界。

## Solution

交付一个手机竖屏优先、可安装并连接真实 BabyForge 服务的 HarmonyOS 原生内测版。客户端使用 ArkTS 与 ArkUI 构建登录、家庭、今天、记录、成长、探索、奶爸 AI 和设置等原生业务表面，通过清晰的业务资源适配层复用同仓账号、家庭、照护事件、规则、知识内容、媒体资产和服务接口。

主导航使用五位置悬浮圆角底栏：今天、记录、中央抬升的奶爸 AI、成长、探索。设计采用已验证的 B“定稿组合”：今天页使用紧凑信息结构；记录页使用编辑流插画卡；奶爸 AI 使用紧凑入口列表与完整会话区。

今天页依次呈现当前宝宝与自然日、日期条、今日摘要、全宽宝宝相册、今日事项和最近事实。今日摘要把奶量、睡眠、尿布与快速记录入口合并在同一控件中；快速记录只负责跳转到记录工作台，不在今天页重复记录表单。相册独占完整内容宽度，支持横向滑动、位置指示、“查看更多”、大图查看及上一张/下一张切换。

记录工作台使用同一小月龄宝宝的身体局部水彩插画区分喂养、睡眠、尿布、用药、体温和成长；固定字段允许一步确认，变量记录使用原生底部抽屉或完整页面。保存成功后事实立即进入时间线，并提供约五秒撤销入口；撤销执行作废，不删除原始事实。

奶爸 AI 作为中央一级入口，使用原创小月龄宝宝陪伴形象，支持文字、语音、照片和快捷任务。来自其他页面的上下文以可移除卡片显示且不自动发送；任何事实写入都先生成可编辑草稿并由照护者确认。

成长、探索与设置采用已确认原型的信息层级，但不以手机端精简为理由删除桌面能力。成长保留概览、完整曲线、阶段详情、成长历史、里程碑、计划和 AI 解读；探索保留疫苗、疾病主题、器官学习、第三方经验、来源与受控 3D；设置保留账号、家庭、宝宝档案、提醒联系人、临时访客、自定义模型、同步与本地数据管理。

所有原生页面通过同一个版本化业务资源合同读取和写入共享业务源。页面可以采用不同布局与系统交互，但账号、权限、事实、计划、测量、里程碑、内容、媒体、AI 能力、派生摘要和状态枚举必须与 Web 客户端一致；原型示例数据不得进入正式实现。

## User Stories

1. As a 家庭照护者, I want 安装一个 HarmonyOS 原生 BabyForge 客户端, so that 我可以像使用其他手机 App 一样完成日常照护任务。
2. As a 已登录用户, I want 冷启动后恢复账号、家庭和当前宝宝, so that 我不必每次重新选择工作空间。
3. As a 无法恢复会话的用户, I want 看到明确的登录或重试状态, so that 我不会面对空白页或无限加载。
4. As a 家庭 Owner, I want 在原生界面管理账号、家庭与设置入口, so that 这些能力不占用主要照护导航。
5. As a 家庭 Member, I want 只看到与成员权限一致的操作, so that 客户端不会因平台差异扩大权限。
6. As a 照护者, I want 通过五位置底部导航在今天、记录、奶爸 AI、成长和探索之间切换, so that 高频目的地始终可达。
7. As a 照护者, I want 中央奶爸 AI 明显但仍表现为一级标签, so that 我不会把它误认为新增记录按钮。
8. As a 照护者, I want 底栏所有标题完整位于圆角控件内部, so that 当前标签和每个目的地都清晰可读。
9. As a 照护者, I want 重复点击当前主标签时返回该标签根页面或顶部, so that 我能快速恢复到已知位置。
10. As a 照护者, I want 每个主标签保留自己的导航栈、输入和滚动位置, so that 切换任务不会丢失上下文。
11. As a 照护者, I want 系统返回手势只处理当前标签栈, so that 返回行为符合 HarmonyOS 习惯且可预测。
12. As a 照护者, I want 今天页首先显示当前宝宝、自然日和日期条, so that 我知道正在查看谁以及哪一天的数据。
13. As a 照护者, I want 今天摘要紧凑展示已确认的奶量、睡眠和尿布事实, so that 我能快速理解当天状态。
14. As a 照护者, I want 快速记录入口直接并入今日摘要, so that 首页更紧凑且不会重复记录页功能。
15. As a 照护者, I want 点击快速记录后进入统一记录工作台, so that 所有事实都从同一个可信入口保存。
16. As a 照护者, I want 今天摘要不把缺失数据当作零, so that 未记录不会被误解为没有发生。
17. As a 家庭成员, I want 今天页在摘要后看到宝宝真实生活照片, so that 数据之外仍能感受到当天的生活上下文。
18. As a 家庭成员, I want 相册独占一整块内容宽度, so that 照片具有足够的观看面积且不与摘要争抢空间。
19. As a 家庭成员, I want 在相册中横向滑动照片, so that 我可以自然浏览当天的多张照片。
20. As a 家庭成员, I want 看到当前照片位置和下一张提示, so that 我知道相册可以继续滑动。
21. As a 家庭成员, I want 通过“查看更多”进入完整照片浏览, so that 我能查看当天更多照片。
22. As a 家庭成员, I want 点击照片查看大图, so that 我能看清照片细节。
23. As a 家庭成员, I want 在大图中切换上一张和下一张, so that 我不必退出后逐张重新打开。
24. As a 家庭成员, I want 大图浏览显示照片时间和简短说明, so that 我能理解照片发生的上下文。
25. As a 家庭成员, I want 使用系统照片选择器新增照片, so that 应用不需要自建文件选择体验。
26. As a 隐私敏感用户, I want 相册照片不会自动发送给奶爸 AI, so that 我的宝宝照片只在明确选择和再次发送后上传。
27. As a 隐私敏感用户, I want 分享和报告默认排除原始照片, so that 照护数据导出不会意外泄露影像。
28. As a 照护者, I want 在相册后看到今日事项, so that 作息、营养和安全照护提醒仍保留在首页。
29. As a 照护者, I want 今日事项明确区分进行中、待处理和已完成, so that 我能快速判断下一步而不依赖颜色猜测。
30. As a 照护者, I want 在首页看到按实际发生时间排列的最近事实, so that 我可以完成家庭交接。
31. As a 照护者, I want 进入记录页后首先看到六类高频事实入口, so that 我能快速找到喂养、睡眠、尿布、用药、体温和成长。
32. As a 照护者, I want 记录入口使用可识别的宝宝身体局部插画, so that 我能在不阅读大段文字时快速定位任务。
33. As a 照护者, I want 每张记录卡只有一个主要动作, so that 操作不会被菜单和次级入口干扰。
34. As a 照护者, I want 固定字段事实可以一步确认, so that 高频记录尽可能省时。
35. As a 照护者, I want 奶量、时间、剂量或测量值等变量通过原生底部抽屉填写, so that 表单保持聚焦且适合单手操作。
36. As a 照护者, I want 睡眠一次录入完整开始和结束时间, so that 系统只保存已经发生的睡眠事实而不是计时状态。
37. As a 照护者, I want 用药记录明确实际药品、剂量、单位和方式, so that 已发生事实不会被误认为用药计划。

40. As a 照护者, I want 保存成功后立即在时间线看到同一事实, so that 我能确认操作结果。
41. As a 照护者, I want 保存后获得轻触觉反馈和约五秒撤销入口, so that 我可以快速纠正误操作。
42. As a 照护者, I want 撤销只作废事实并保留审计关系, so that 家庭记录始终可追溯。
43. As a 照护者, I want 在断网时继续查看最近成功同步的今天页和时间线, so that 暂时无网不会完全阻断照护交接。

47. As a 照护者, I want 同一事实发生版本冲突时保留我的输入并提示刷新, so that 客户端不会静默覆盖另一位家庭成员的修改。
48. As a 照护者, I want 从中央入口进入奶爸 AI 的紧凑主页, so that 我能快速选择喂养观察、睡眠观察、今日总结或记录草稿。
49. As a 照护者, I want 奶爸 AI 默认续接最近会话并允许显式新建对话, so that 连续交流和任务切换都可控。

94. As a 照护者, I want 奶爸 AI 的能力注册表在两端一致, so that 宝宝上下文、知识检索、快速记录、今日分析、饮食建议、详细分析、阶段问答、疾病解释、预评估、成长解读、成长计划、报告解读、就医摘要和照护交接都保持可达。
95. As a 照护者, I want AI 会话、生成中、停止、失败、来源、能力产物和草稿状态在切换页面后保持, so that 原生会话不是一次性快捷问答。
96. As a 用户, I want 在设置中管理语言、昵称和宝宝出生资料, so that 年龄、阶段、疫苗和时间计划使用同一份最新资料重算。
97. As a 家庭 Owner, I want 管理关键更新邮件和家庭通知联系人, so that 已有家庭提醒能力在手机端可用。
98. As a 家庭 Owner, I want 创建、复制和撤销临时只读访客链接, so that 临时分享仍遵守相同权限与脱敏规则。
99. As a 用户, I want 查看同步状态、重试同步、清理本机缓存并安全退出, so that 本机维护动作不会误删云端共享记录。
100. As a 用户, I want 配置或清除当前账号的自定义模型且 API Key 不回显, so that 奶爸 AI 的现有模型设置能力和秘密边界不因平台变化而退化。

## Implementation Decisions

- 客户端使用 ArkTS 与 ArkUI 构建系统原生业务表面。ArkWeb 研究壳只作为历史原型，不作为原生内测版的主要页面承载方式。
- 登录、家庭、今天、记录、成长、探索、奶爸 AI 和设置均由原生层负责导航、返回栈、滚动、键盘避让、加载、空状态、错误、重试和保存反馈。
- 复杂 3D 可以作为原生页面内的受控 Web 内容表面；它不得拥有一级导航、账号状态或业务写入能力。第三方原文使用系统浏览器。
- Web 与 HarmonyOS 客户端共享账号、家庭成员关系、宝宝档案、照护事件协议、确定性规则、知识内容、媒体资产与服务接口；不共享 React 组件或页面实现，不建设鸿蒙独立业务副本。
- 原生业务资源适配层是客户端与共享业务源之间的唯一主要测试缝。页面依赖适配层提供明确的加载、成功、空、失败、离线、冲突和只读状态。
- 原生端不得把桌面展示值、里程碑、阶段文案、计划、疫苗节点、标准线、AI 能力清单或设置枚举复制为 App 常量。原型中的示例值仅用于验证布局；实现必须由共享资源适配层返回页面模型。
- 页面能力与唯一共享资源合同如下。App 可以重新组织信息层级与原生交互，但不得减少业务能力、改变字段语义或维护平台专属事实状态：

| 原生表面 | 与桌面端共用的唯一业务资源 | App 端允许的差异 |
| --- | --- | --- |
| 登录与家庭 | 账号会话、家庭成员关系、角色权限、当前宝宝 | 原生登录控件、系统返回与错误呈现 |
| 今天 | `baby`、有效 `CareEvent`、`carePlanItems`、确定性今日摘要、相册媒体 | 紧凑摘要、全宽相册、手机日期条与列表层级 |
| 记录 | 统一照护事件协议、记录字段/枚举/校验、纠正与作废关系、同一时间线 | 原生编辑流卡片、底部抽屉或完整页面 |
| 成长 | `baby`、`growthMeasurements`、`milestoneRecords`、`carePlanItems`、`adminTaskRecords`、年龄策略、`getGrowthStageContent`、国家标准评估、成长曲线与确定性解读 | 手机卡片顺序、指标切换与抽屉呈现 |
| 探索 | 疫苗计划、疾病注册表、器官内容、审核知识包、第三方经验索引与来源元数据 | 原生主题卡、系统浏览器打开外部原文、受控 3D 容器 |
| 奶爸 AI | 能力注册表、会话、已确认事实上下文、审核知识检索、Guardrail 与草稿确认合同 | 紧凑入口、语音/照片系统入口与手机会话布局 |
| 相册 | 同一家庭媒体服务、照片元数据、权限与上传状态 | 系统照片选择器、全屏大图与滑动手势 |
| 设置 | 账号、家庭、宝宝档案、提醒联系人、访客链接、偏好、模型配置与同步元数据 | 原生分组列表、系统权限入口与本机缓存操作 |

- 共享业务资源合同按能力域提供版本化读模型和命令，不按客户端复制数据。最低合同集合如下：

| 合同能力域 | 读取模型 | 允许命令 |
| --- | --- | --- |
| 会话与家庭 | 当前用户、会话恢复结果、家庭、成员、角色、当前宝宝 | 登录、注册、验证、重置密码、第三方登录、创建/加入家庭、成员管理、退出 |
| 今天 | 指定当地自然日的宝宝抬头、确定性照护摘要、饮食参考、AI 今日分析、成长计划、今日事项、最近事实和相册摘要 | 完成计划项、打开统一记录流；不直接创建页面专属事实 |
| 记录 | 记录定义、字段枚举、单位、默认策略、事实时间线、每日摘要、关注事项、咨询问题和记录人 | 创建、纠正、作废事实，更新关注事项、咨询问题、计划与里程碑 |
| 成长 | 有效测量、冲突、最新指标、曲线、参考线、年龄口径、阶段内容、成长历史、里程碑、计划、确定性摘要 | 发起统一成长记录流，更新计划/里程碑，打开 AI 解读 |
| 探索 | 疫苗计划、疾病注册表、器官与解剖锚点、审核知识、经验索引、来源和受控 3D 元数据 | 打开统一记录/预评估流程、更新疫苗事实、打开系统浏览器 |
| 奶爸 AI | 能力注册表、会话、消息、来源、能力产物、上下文卡、事实草稿和最低行动要求 | 新建/继续会话、发送/停止、移除上下文、生成/编辑/确认/丢弃草稿 |
| 相册 | 家庭照片、时间、说明、文件状态、权限、缩略图与原图地址 | 上传、拍摄导入、修改元数据、下载、删除 |
| 设置与分享 | 语言、昵称、宝宝档案、邮件订阅、联系人、访客链接、模型配置摘要、同步和缓存元数据 | 更新设置、管理联系人/访客链接/模型配置、重试同步、清理本机缓存 |

- 每个读取模型必须携带合同版本、生成时间、数据时区、权限/只读状态和可用于刷新或冲突判断的源版本。页面不得根据缺失字段自行猜测业务默认值。
- 每个事实写入命令必须携带幂等标识；纠正和作废必须携带期望版本。服务端确认是唯一成功标准，原生本地状态只保存输入草稿、缓存和待确认结果。
- HarmonyOS 客户端不得直接连接 D1、R2 或读取 Web 本地存储。它只通过 BabyForge 服务合同访问共享业务源；媒体二进制仍受家庭授权和短效访问边界保护。
- Web 可以在迁移期通过 Web 适配器包装现有领域模块，HarmonyOS 通过 ArkTS 适配器消费同一合同。一个页面进入“完成”前，两端必须对同一合同版本和同一夹具生成等价业务字段；只允许排序容器、卡片尺寸、导航信息和系统交互等表现元数据不同。
- 桌面能力可达清单是原生交付的绑定验收清单：

| 能力区域 | 必须保留的桌面能力 | 原生入口 |
| --- | --- | --- |
| 登录与家庭 | 登录、注册、邮箱验证、密码重置、已支持的第三方登录、创建/加入家庭、邀请与成员角色 | 启动/登录流与宝宝/账号入口 |
| 今天 | 当前宝宝与年龄、当地日期、照护汇总、饮食建议、今日分析、成长计划、今日事项、最近事实、相册和记录入口 | “今天”根页面及其二级详情 |
| 记录 | 六类高频事实、基础资料、症状、生病、照护动作、专业记录、关注事项、咨询问题、每日摘要、日期/类型筛选、详情、纠正、作废、记录人和就医摘要 | “记录”根页面、底部抽屉和完整记录页面 |
| 成长 | 三项指标概览、直接记录、完整曲线、国家标准参考、冲突提示、阶段详情、年龄口径、家长行动、成长历史、里程碑、计划和 AI 解读 | “成长”根页面及曲线/阶段/历史详情 |
| 探索 | 疫苗计划、疾病搜索与完整主题、器官学习、关联疾病、受控 3D、预评估入口、第三方经验、适龄筛选和来源 | “探索”根页面及三个健康主题与经验详情 |
| 奶爸 AI | 完整能力注册表、最近会话、新对话、文字/语音/照片/报告输入、停止生成、来源、产物、草稿确认、就医摘要与照护交接 | 中央“奶爸 AI”根页面、会话与报告详情 |
| 相册 | 上传、拍摄导入、横向浏览、查看更多、大图切换、按日期浏览、时间/说明、下载、删除和权限反馈 | 今天页相册、沉浸相册与系统照片选择器 |
| 设置与分享 | 语言、昵称、宝宝出生资料、关键更新邮件、通知联系人、临时访客链接、自定义模型、同步状态、重试、本机缓存清理和退出 | 宝宝/账号入口下的设置分组页面 |

- 底部主导航固定为今天、记录、中央奶爸 AI、成长、探索五个位置。中央宝宝图标视觉抬升，但标签文字与其他标题必须完整包含在悬浮圆角控件内。
- 每个主标签维护独立导航栈、滚动位置和临时输入。重复点击当前标签时，深层页面回根，根页面回顶部。
- 手机竖屏使用底部导航和单列任务流；折叠屏展开态使用侧边导航及列表—详情双栏。响应式变化不改变事实语义和主要操作。
- 今天页采用已验证 B 定稿组合：当前宝宝和自然日、日期条、合并式今日摘要、全宽相册、今日事项、最近事实。
- 今日摘要使用三个确定性事实槽位与一个快速记录入口。缺失事实显示未记录，不显示零；快速记录跳转统一记录工作台，不在今天页保存事实。
- 相册是全宽横向分页区域，使用滑动吸附、当前位置指示与“查看更多”。点击照片打开沉浸大图，支持关闭、上一张、下一张、照片序号、时间和说明。
- 新增照片调用系统照片选择器。照片只在家庭授权边界内加载；缩略图和大图具备加载占位、失败重试和缓存时间说明。
- 原始照片不会自动进入 AI、报告或分享。发送给 AI 前显示缩略图和用途说明，并要求用户再次发送；包含照片的导出再次明确确认。
- 今日事项复用现有作息、营养和安全照护计划语义，明确显示状态与完成动作；色彩只辅助识别，不承担状态含义。
- 记录页采用编辑流：两列非等高模块化插画卡，高频任务获得更大面积，每卡一个主要动作。六类高频事实与低频资料入口保持现有领域边界。
- 固定字段记录允许一步确认；变量记录进入原生底部抽屉；用药或长专业字段进入完整页面。未保存抽屉下滑关闭前要求确认。
- 今天、成长和 AI 可以在当前页面视觉上下文发起预选记录流程；它们只呈现统一记录模块，不拥有页面专属表单、校验器或写入器。成长测量继续一次保存一个类型、数值、测量日期与来源，字段和单位与桌面记录中心一致。
- 睡眠记录只保存完整开始与结束时间，不引入开始计时、未结束睡眠或后台计时。
- 所有正式事实继续使用照护事件协议，保留实际发生时间、记录时间、记录人、来源、状态、版本、纠正和作废关系。
- 保存成功只在服务端确认后显示。成功后立即更新事实时间线与确定性摘要，触发克制触觉反馈并提供约五秒撤销；撤销执行作废。
- 原生内测版支持读取最近同步缓存和本机可恢复草稿，但不排队离线创建照护事实、不后台补传、不自动合并冲突、不显示假成功。
- 请求响应不明时进入结果待确认状态，并在联网后按事件幂等标识查询服务端结果；确认不存在后才允许用户重新提交。
- 奶爸 AI 采用紧凑入口列表与独立全屏会话区。中央入口和会话状态使用同一原创小月龄水彩宝宝形象。
- AI 上下文以可移除卡片展示但不自动发送；文字、语音、照片和快捷任务进入同一会话输入模型。切换标签不得丢失未发送输入和滚动位置。
- AI 只能生成可编辑记录草稿；照护者明确确认后才调用正式事实写入。最低行动要求和确定性规则不能被 AI 创建、修改或降低。
- 轻量解释与确认使用底部抽屉，长分析、完整报告和可分享材料使用独立页面。
- 插画使用已确认的 2–4 月龄小月龄宝宝水彩母版。中央形象保持圆润脸颊、细软深色头发、明亮眼睛、自然微笑和暖象牙纸感；禁止心形、机器人、植物精灵、亮面 3D 玩具、用户宝宝替身或医生人格。
- 六类记录插画固定使用相应身体局部：嘴巴与脸颊、闭眼与睫毛、纸尿裤小屁屁与脚丫、小嘴与喂药勺、额头与脸颊、小脚与软量尺。图片不烘焙文字、数字、按钮或医学结论。
- HarmonyOS Sans、HarmonyOS Symbol、系统触控反馈和平台动效作为原生骨架；品牌层使用暖象牙、珊瑚、鼠尾草和少量薰衣草。颜色不表示医学严重度。
- 常规动效控制在约 180–280ms。宝宝只使用克制的呼吸、侧耳、眨眼和微笑；系统减少动态效果开启后退化为静态状态变化。
- 原生内测版连接真实 BabyForge 服务和家庭数据，但不代表完成 AppGallery 正式发布。医疗安全正式发布仍受独立发布门禁约束。
- 当前服务 API 和数据协议优先复用，不为界面原生化新增业务表或复制规则。只有适配现有协议确有缺口时，才在独立票中提出向后兼容的接口扩展。
- 原生页面必须显式实现加载、成功、真实空状态、离线缓存、失败重试、只读、无权限、冲突和结果待确认状态；这些状态来自共享业务资源合同，不由插画或本地占位值推断。
- 原型只证明信息架构、密度、交互与视觉方向。原型内所有宝宝资料、指标、日期、照片、里程碑、计划、文章和 AI 结果均为布局夹具，正式 App 禁止读取原型模块或把其值复制为业务常量。

## Testing Decisions

- 测试只断言用户可观察行为、共享业务契约和安全边界，不断言 ArkUI 内部组件层级、私有状态名称或具体布局实现。
- 最高测试缝是“原生 App 壳 + 可替换业务资源适配层”。测试使用确定性假服务驱动登录、家庭、照护事件、相册、今日事项、成长、探索和 AI 状态，避免依赖生产网络。
- 业务资源适配层合同测试必须覆盖合同版本、权限、时区、源版本、分页、缓存时间和错误类型；遇到未知合同版本或缺少必需业务字段时显示可恢复错误，不以本地常量补齐。
- 共享业务契约测试覆盖账号恢复、家庭授权、照护事件新增/纠正/作废、冲突、幂等查询、时间口径、确定性摘要和 AI 草稿确认，确保 Web 与原生客户端解释一致。
- 原生端到端测试覆盖冷启动、五标签导航、独立返回栈、今天到记录保存再回到时间线、相册滑动与大图切换、今日事项、AI 上下文与草稿确认。
- 跨端同源契约测试使用同一组账号、家庭、宝宝、照护事件、测量、里程碑、计划、内容和媒体夹具分别驱动 Web 与原生资源适配层；两端输出的事实数量、有效状态、字段单位、时间口径、摘要、阶段、里程碑、标准评估、来源与权限必须一致，只允许布局元数据不同。
- 跨端写入契约测试从两端提交同一合法输入，验证生成的事件类别、发生时间、记录时间、记录人、来源、载荷、状态和审计关系等价；重复幂等标识、过期版本、响应不明和只读权限必须得到同类结果。
- 每个桌面一级或二级业务能力都必须在原生信息架构中有可达入口。自动化能力清单测试阻止因原生页面精简而遗漏记录低频事实、完整成长曲线、阶段详情、成长历史、AI 报告/交接/计划、提醒联系人、访客链接或数据管理。
- 能力清单测试以版本化清单为输入，逐项验证桌面入口和原生入口都可达；新增桌面业务能力时，如果未声明原生入口、明确延期票或平台不适用原因，CI 必须失败。
- 页面模型黄金夹具至少覆盖今天、记录、成长、疫苗、疾病、器官、经验、奶爸 AI、相册、设置和访客视图，并分别包含有数据、真实空状态、只读、离线缓存与失败状态。
- 网络状态测试覆盖离线缓存、可恢复草稿、超时、响应不明、手动重试、409 冲突、只读权限和服务端失败，所有路径都不得显示假成功。
- 视觉与布局测试至少覆盖 360、390、430 手机宽度、系统大字体、长中文文案、底栏标题 containment、键盘弹出和安全区。
- 折叠屏测试覆盖窗口收窄/展开、底栏到侧栏切换、列表—详情双栏和各标签状态保留。
- 相册测试覆盖横向滑动、位置指示、查看更多、点击大图、上一张/下一张、加载失败、无照片、单张照片、多张照片和照片权限拒绝。
- 记录测试覆盖六类入口、一步确认、变量抽屉、保存反馈、五秒撤销、永久作废、纠正、跨午夜睡眠、无数值体温和实际用药字段。
- AI 测试覆盖默认续接、新对话、上下文移除、不自动发送、文本/语音/照片入口、上传前确认、草稿编辑、明确确认、工具失败和最低行动不可降低。
- 无障碍测试覆盖读屏名称、焦点顺序、触控目标、动态文字、非颜色状态表达、减少动态效果和大图浏览按钮语义。
- 3D 受控内容测试只验证失败关闭、站内边界、外部链接交给系统浏览器以及 3D 失败不影响原生正文。
- 现有 Web 领域单元测试、照护事件协议测试、AI Guardrail 测试和 Playwright 移动视觉测试作为业务语义和主要流程的先例；原生测试对齐这些外部行为，不复制 Web DOM 断言。
- 内测交付前运行原生目标测试、共享契约测试、类型检查、构建、真机核心路径与最终差异审查；AppGallery 发布前的医疗安全 Eval 和发布验收不由本规格替代。

## Out of Scope

- 将 React 页面整体嵌入 ArkWeb 作为正式原生业务界面。
- 建设第二套鸿蒙账号、家庭、事实、规则、知识或 AI 数据源。
- AppGallery 正式发布、商店素材、正式签名与完整发布运营流程。
- 平板完整信息架构；本轮只要求手机竖屏和折叠屏展开态响应式基础。
- 持久化离线事实队列、后台自动补传、静默重试和自动冲突合并。
- 睡眠计时、未结束睡眠、后台实时任务、硬件设备接入。
- AI 自动确诊、处方、用药剂量、健康评分或绕过确定性规则的行动建议。
- 照片自动上传 AI、默认包含照片的报告或无确认的照片分享。
- 原生重写复杂 3D 查看器；3D 保持受控混合表面与原生降级内容。
- 复制参考 App 的品牌、广告、青绿色主题、亮面 3D 角色或未被 BabyForge 领域模型支持的功能。
- 在插画中烘焙标题、数值、状态、按钮或医学严重度。
- 对现有 Web 客户端进行无关重构或视觉改版。

## Further Notes

- 已验证原型的获胜组合为 B“定稿组合”：今天页紧凑、记录页编辑流、奶爸 AI 紧凑列表。
- 成长、探索与宝宝/账号设置根页面已经确认定稿；成长在当前页调用统一测量抽屉，探索采用一体化宝宝水彩横幅和主题卡，设置使用原生分组列表承载完整桌面能力。
- “所有页面与桌面端同源且能力不丢失”是绑定约束：不能通过复制 App 常量、重新计算摘要、另建里程碑表或删除二级入口来完成原生化。
- 今天页最终相册不是摘要旁的小卡，而是摘要之后的全宽横向浏览模块；快速记录不是独立首页卡，而是今日摘要第四入口。
- ArkWeb 壳决策保留为早期研究原型的历史记录；本规格的原生业务表面方向由“共享业务源、不共享界面”的后续决策取代。
- 原生内测版不排队离线写入照护事实是绑定约束，不应在实现过程中以“体验优化”为由弱化。
- 小月龄宝宝与六类身体局部插画已经完成风格标定，可作为首批原生资源；后续图片必须保持同一宝宝身份和水彩笔触。
- 插画资产的最终像素尺寸、裁切安全区和压缩参数属于实现票中的可调参数，不再构成产品规格待确认项；任何调整都不能改变已确认构图、宝宝身份或原生文字留白。
- 本规格适合下一步按阻塞关系拆成 tracer-bullet tickets；每票应保持一个独立验收与回滚边界。
