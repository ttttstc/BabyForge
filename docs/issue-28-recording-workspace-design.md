# Issue #28：人工事实记录工作台方案

- 状态：已确认
- 日期：2026-08-07
- 关联：Issue #6、#7、#8、#9、#28、#29
- 决策记录：[ADR-0005](./adr/0005-recording-workspace-boundary.md)

## 1. 唯一目标

让家庭成员在低压力、夜间和单手操作场景下，快速保存已经发生的主要照护事实，并从同一事实账本查看单日时间线和今日确定性汇总。

核心闭环：

```text
选择主要记录类型
→ 输入或确认本次事实
→ 保存为 CareEvent
→ 单日时间线立即出现
→ 今天页四项汇总确定性重算
→ 随时纠正或作废
```

## 2. 页面边界

### 记录工作台

“记录”是创建、核对和管理事实的唯一入口。默认突出六类主要事实：

1. 喂养；
2. 睡眠；
3. 尿布；
4. 用药；
5. 体温；
6. 成长。

症状观察和专业结论仍是事实，保留为弱化的“其他记录”入口。宝宝档案、关注事项和咨询问题暂作为兼容现有流程的次级入口保留；照护计划继续留在今天/阶段页面。它们都不进入六类 P0 汇总，也不改变“今天查看、记录操作”的主路径。

### 今天页

“今天”只负责查看：

- 展示喂养、睡眠、尿布、用药四项汇总；
- 点击卡片查看对应单日事实；
- 点击“+”跳转记录工作台并预选类型；
- 不直接展示或提交记录表单。

从今天页进入时，保存成功后返回今天页；直接进入记录工作台时，保存后留在工作台。

## 3. P0 记录类型

所有记录沿用现有 `CareEvent` 核心协议，不新增表或核心字段。

| 用户记录 | `kind` | `category` | 最小载荷与规则 |
| --- | --- | --- | --- |
| 母乳亲喂 | `caregiver_observation` | `breastfeeding` | 不要求估算奶量；类型按钮可一步保存 |
| 母乳瓶喂 / 配方奶 | `caregiver_observation` | `bottle_feeding` | `milkType`、`amountMl`、`unit: mL`；奶量默认 50，保存即确认本次实际摄入量 |
| 睡眠 | `caregiver_observation` | `sleep` | `occurredAt` 为开始时间，`payload.endedAt` 为结束时间；一次录入完整区间，结束必须晚于开始 |
| 尿布 | `caregiver_observation` | `diaper` | `kind: urine \| stool \| both`；三种类型均可一步保存 |
| 用药 | `caregiver_observation` | `medication` | 实际药名、剂量、单位、给药方式；不读取或比较计划 |
| 体温测量 | `measurement` | `temperature` | 数值、`°C`、测量时间、测量部位/方法 |
| 体温观察 | `caregiver_observation` | `temperature_observation` | 数值为空时明确保存“数值未记录”；不得解释为正常或参与数值统计 |
| 体重 / 身长 | `measurement` | `growth_measurement` | `type: weight \| length`、实际数值、单位、来源；最近值只展示参考，不复制到新测量 |

事件的 `babyId`、`actor`、`recordedAt` 和 `source` 继续由统一提交入口补全。事件载荷使用现有开放 JSON，不需要 D1 迁移；现有宝宝、类别、发生时间索引可以继续使用。

前端提交入口与 API 写入入口使用同一组最小载荷校验，拒绝缺少必要字段、数值无效或结束时间早于开始时间的事件；不建设通用 Schema 框架。

## 4. 交互规则

### 一步保存

当按钮本身已经完整表达事实时直接保存：母乳亲喂、尿、便、尿和便。保存成功后，事实会出现在时间线并提供永久“作废”入口；作废实际调用现有生命周期协议。

### 轻表单确认

含本次变量的记录必须先打开轻表单：瓶喂、睡眠、用药、体温、体重和身长。表单默认只显示完成本次事实所需的字段。

允许的固定默认值：

- 当前宝宝、当前记录人、当前时间；
- 瓶喂 `50 mL`；
- 体温 `°C`；
- 体温数值从 `36.5` 开始，可清空；这只是减少输入的起点，不代表系统判断正常；
- 体重 `kg`；
- 身长 `cm`；
- 睡眠结束时间为当前时间。

已有体重和身长在新表单中带出最近一次值，用户可以直接改写或清空；不存在最近值时保持空白。体温数值为空时仍可保存，但必须保存为体温观察而不是测量。

### 撤销、纠正和作废

- 撤销：保存后的便捷称呼，实际调用永久作废；
- 纠正：使用现有版本化纠正协议，新事件通过 `correctedFromId` 追溯原事件；
- 作废：任何有效记录在任何时间均可作废；
- 不提供物理删除或恢复栈；
- 纠正和作废后，时间线与今天汇总从有效事实重新计算。

## 5. 单日事实时间线

- 默认日期为设备当地今天；
- 日期选择器可以切换到任意单日；
- 按实际发生时间倒序；
- 支持全部、喂养、睡眠、尿布、用药、体温、成长和其他事实筛选；
- 主时间线只展示当前有效版本，每条展示发生时间、核心值和记录人；
- 已纠正和已作废版本从记录详情的修改历史查看；
- 支持详情、纠正和作废；
- 补录通过普通新增表单选择过去时间完成；
- 不提供最近七天、无限滚动、复杂报表或复制为新记录。

“今日”按查看设备的当地自然日计算，事件继续以 UTC 保存。首期不增加家庭固定时区。

## 6. 今日汇总

汇总只读取 `status === active` 的已保存事实；不存在的记录显示“暂无记录”或破折号，不解释为实际没有发生。

### 喂养

- 母乳亲喂次数；
- 瓶喂实际摄入总量；
- 母乳瓶喂与配方奶次数；
- 最近一次喂养时间。

### 睡眠

- 与今日自然日重叠的累计时长；
- 与今日重叠的睡眠段数；
- 跨午夜记录只累计落在今日范围内的部分。

### 尿布

- 尿湿次数；
- 排便次数；
- `both` 同时计入两项，但时间线仍只显示一条事实。

### 用药

- 今日实际用药次数；
- 最近一次用药时间；
- 不显示计划数、完成比例或剂量建议。

体温和成长不进入今天页四项概览，继续在记录时间线及其对应展示页面查看。

## 7. 保存、同步和冲突

沿用 Issue #7 的事件级在线写入：

- 新增按事件 ID 独立写入；
- 保存成功后才显示正式成功状态；
- 网络失败时回滚未同步的本地结果，并在当前页面保留本次输入供手动重试；
- 保存失败时回滚本地事件，表单保留输入供用户手动重试；不建设持久化队列；
- 纠正和作废携带当前 `version`；
- `409` 时恢复服务端当前版本，保留用户输入，提示刷新后重新提交；
- 不自动合并、不后台重传、不静默覆盖。

## 8. 响应式页面

桌面端使用双栏：左侧为类型入口和当前表单，右侧为单日时间线。移动端使用单列：类型入口在前、时间线在后；轻表单使用底部抽屉或轻页面，同一套字段和校验逻辑复用。

一步保存按钮提供明确文本，不仅依赖图标或颜色。保存中、失败、冲突、已作废状态具备可读文本和读屏提示。

## 9. 现有代码改造边界

- `RecordCenter.jsx`：改造成六类主要事实入口、次级其他事实入口和单日时间线；保留现有低频资料入口以避免无关回退。
- `QuickRecordPanel.jsx`：不再出现在今天页；其一键保存逻辑可收敛进新的记录工作台后删除或缩减。
- `ContextInspector.jsx`：删除直接记录表单，只保留今天汇总与跳转。
- `CareOverview.jsx`：改为四项确定性今日汇总，不再展示最近 24 小时口径。
- `careSummary.js` / `careEvents.js`：增加最小载荷校验、设备当地单日筛选和四项纯函数聚合；保持 `CareEvent` 核心协议不变。
- `functions/_shared/care.js`：在 API 写入前复用同一组最小载荷校验，不改变现有端点协议。
- `App.jsx`：沿用统一提交和同步入口，补齐失败回滚、冲突反馈和来源页返回。
- Cloudflare API 与 D1：复用现有新增、纠正、作废和查询接口，不新增数据表。

## 10. 实施切片

1. **领域闭环**：最小载荷校验、单日选择器、四项聚合及单元测试。
2. **记录工作台**：六类入口、一步保存、轻表单和单日时间线。
3. **记录管理**：详情、纠正、永久作废和失败重试。
4. **今天联动**：四项汇总、预选类型跳转、保存后返回和即时重算。
5. **交付验证**：移动端单手流程、键盘与读屏、冲突/网络失败、视觉回归、lint、测试和构建。

## 11. 关键验收场景

1. 月嫂点击“尿”后一步保存，时间线和今天尿湿次数立即更新；之后仍可作废。
2. 爸爸打开配方奶，默认看到 `50 mL`，修改或直接确认后保存实际摄入量。
3. 用户一次录入跨午夜睡眠，两个自然日分别只累计各自覆盖时长。
4. 用户空值保存体温，只产生“数值未记录”的观察，不显示正常值、不进入体温数值统计。
5. 最近体重和身长作为新表单的输入起点带出，用户清空后仍可取消本次保存，不能把未确认的值解释成新测量。
6. 纠正奶量或作废尿布后，单日时间线保留审计关系，今天汇总确定性回滚。
7. 两名照护者同时新增不同事实，两条均保留；同时修改同一事实时后提交者收到冲突。
8. 网络失败不显示保存成功，当前输入保留，用户可以手动重试。
9. 从今天页某项“+”进入时自动预选类型，保存后回到今天页并看到新汇总。
10. 移动端进入记录页后能快速找到六类入口，高频记录无需填写自由文本。

## 12. 明确非目标

本 Issue 不建设：睡眠计时或未结束状态、头围、辅食和其他饮品、用药计划或完成比例、常用模板、复制记录、附件、七日视图、复杂报表、AI/语音/自动识别、硬件接入、持久化离线队列、后台补传和自动冲突合并。
