# 子议题 5：隔离演示沙盒

## 唯一目标

提供固定 `demo / 123456` 的产品能力演示入口，但不让演示身份进入正式用户或生产家庭授权体系。

## 设计

- 只在开发环境或显式设置 `VITE_ENABLE_DEMO=true` 的演示构建启用，使用每个浏览器独立的虚拟数据沙盒。
- 数据为虚构宝宝，不访问生产 D1、R2、Resend、Google 或 OpenAI Secret。
- 不创建正式 User、Household membership 或持久化家庭数据。
- 登录页明确标注“演示模式”；退出或刷新可重置沙盒。

## 实现边界

- 公网部署流程显式开启演示入口；普通生产构建默认不包含演示凭据。
- 登录成功后始终从 `createDemoWorkspace()` 创建虚构数据，不读取 IndexedDB，也不恢复上次演示修改。
- 体验内容和奶爸 AI 使用浏览器内预置结果；照片、同步、设置和正式账号接口均不参与演示流程。
- 迁移 `0016_disable_public_demo_accounts.sql` 停用旧的共享 Guest 演示账号及会话，避免它们继续进入正式家庭授权链路。

## 非目标

生产 demo 账号、共享 D1 演示家庭、真实照片、真实邮件、跨浏览器同步。

## 验收

固定凭据可进入演示；刷新后恢复虚构初始数据；演示浏览、体验内容和 AI 不发出 `/api/*` 请求；演示操作不影响正式账号和生产数据；构建产物不包含生产 Secret。
