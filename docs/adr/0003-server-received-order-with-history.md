# ADR-0003：按服务端接收顺序写入并保留修订历史

- 状态：已采纳
- 日期：2026-08-06

## 背景

家庭设备数量少，实时协作要求不高。复杂冲突提示会打断快速记录，也无法替用户判断哪一次输入更可信。

## 决策

事件级接口由服务端接收顺序决定当前版本；不返回 409，也不要求用户解决冲突。每次修改或作废前，把前一版本写入修订历史，当前事件保留最新版本。在线页面每 30 秒拉取一次，并在登录、刷新、切回页面和网络恢复时立即拉取；离线写入进入本地 outbox，恢复网络后自动重试。

## 后果

用户得到简单、可预期的“最后一次提交显示为当前版本”行为，同时仍能在审计和导出时追溯历史。由于没有全量数组覆盖接口，两个设备新增事件不会互相覆盖。
