# 原生业务页面可以发起统一记录流程，但不拥有第二套写入逻辑

## 背景

ADR 0005 和 ADR 0007 将照护事实的创建、纠正与作废收敛到统一记录工作台，避免今天页或成长页形成第二数据源。手机端连续操作又要求照护者在成长页直接记录测量；如果强制先切换到底部“记录”标签，会破坏当前任务，但如果为成长页重新实现表单和保存逻辑，又会造成跨端字段、校验和事实状态漂移。

## 决策

今天、成长、奶爸 AI 等原生业务页面可以在当前页面视觉上下文中发起带类型和返回地址的统一记录流程。手机端优先使用原生底部抽屉，长字段使用完整记录页面。

该流程必须复用统一记录模块的字段定义、枚举、单位、默认值策略、权限、校验、幂等标识、服务调用、保存状态、纠正与作废语义。成长页只能传入预选类型、可选指标和返回上下文；它不能直接修改成长读模型，也不能维护 App 专属测量、里程碑或 `GrowthState`。

成长测量仍一次保存一个 `growth_measurement` 事实，包含类型、数值、单位、测量日期和来源。服务端确认后，各平台重新读取同一家庭事实及共享成长派生结果。桌面 Web 与 HarmonyOS 不共享 UI 组件，但共享业务资源合同与外部行为。

本决策只放宽 ADR 0007 的界面入口限制；“成长页不拥有第二事实写入器、不持久化第二份成长状态”的数据边界保持不变。

## 后果

- 照护者可以在成长页少一次标签切换。
- 记录页仍是事实浏览、核对、纠正和作废的统一工作台。
- 原生实现需要把共享记录能力暴露为可从多个页面启动的应用服务或页面模型，而不是复制表单代码。
- 跨端契约测试必须证明同一输入在 Web 与 HarmonyOS 生成等价的照护事件，并在两端得到相同成长页面模型。
