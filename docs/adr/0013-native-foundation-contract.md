# ADR-0013：HarmonyOS 原生基础使用版本化共享资源合同

## 状态

已接受，Issue #70 实施基线。

## 决策

HarmonyOS 内测版的默认 `pages/Index` 使用 ArkUI 原生入口，不把 React 页面装进 ArkWeb。早期 ArkWeb 研究目标保留为 `pages/LegacyWeb`，只用于兼容性回溯和安全导航验证。

原生入口只通过 `/api/native/bootstrap` 及现有账号、家庭命令访问 BabyForge 共享业务源。响应必须包含 `babyforge.native.bootstrap@1.0.0` 合同、生成时间、数据时区、资源源版本、账号、家庭、宝宝和权限；未知版本、缺少字段、网络失败和服务错误都必须转为可恢复状态。ArkTS 与 Web 适配器共享同一份合同夹具，不复制桌面展示值、事实、规则或权限常量。

登录、注册、邮箱验证/重发、密码重置、Google 登录、冷启动恢复、创建家庭、邀请预览/接受、成员邀请和退出由原生壳承载。会话只保存平台会话 Cookie 与最近一次成功的资源缓存，不保存密码、API Key 或待提交照护事实。离线可以展示带过期标记的缓存，但不排队写入事实。

原生一级导航固定为今天、记录、奶爸 AI、成长、探索五个标签。每个标签维护自己的返回栈、滚动位置和临时输入；系统返回先处理当前标签，重复点击当前标签回到根部并回顶。后续页面票只实现布局与业务表面，不改变本基础合同或建立第二套数据源。

## 影响

- 早期 ArkWeb 方案中的“默认加载生产 Web 页面”只适用于历史研究页面，不再是原生内测版入口。
- 后续 #71–#73 页面必须消费同一合同/适配层，并按 `contracts/native-capability-manifest.v1.json` 声明桌面能力入口或延期边界。
- 构建门禁包括 Harmony 静态检查、ArkTS HAP 构建、Web 契约测试和共享能力清单测试。
