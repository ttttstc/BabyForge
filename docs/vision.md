# BabyForge 0–3 岁育儿 3D 工作台

## 页面线框、模块设计与交互方案 V0.1

------

## 1. 产品定义

BabyForge 是一款面向 0–3 岁婴幼儿家庭的成长与疾病认知工作台。

产品围绕三个核心问题展开：

1. 宝宝当前处于什么阶段；
2. 这个阶段重点需要关注什么；
3. 出现某种问题时，身体哪里发生了什么，家长下一步应如何处理。

产品采用与 3DCellForge 相近的工作台结构：

- 左侧管理阶段、疾病和待办事项；
- 中央通过 2D/3D 动画展示宝宝当前状态；
- 右侧解释阶段特点、疾病机制和行动建议；
- 顶部切换成长、疾病、对比和就医模式；
- 当前状态、历史记录和用户设置持续保存。

3DCellForge 已验证了“左侧资产库、中央可视化舞台、右侧检查工具、任务队列、演示模式”的工作台形态。BabyForge 保留这一交互骨架，将模型资产替换为宝宝阶段、身体系统、疾病专题和家庭照护任务。

# 4. 顶部导航设计

## 4.1 左侧区域

显示：

- 产品 Logo；
- 宝宝头像；
- 宝宝昵称；
- 当前日龄或月龄；
- 宝宝切换入口。

示例：

```text
BabyForge | 小舟 · 出生第 6 天
```

家庭存在多个宝宝时，可以通过下拉菜单切换。

## 4.2 中央导航

一级导航：

```text
今天 | 阶段 | 疾病 | 成长 | 日历 | 对比
```

## 4.3 右侧功能

```text
搜索 | 就医模式 | 家庭协作 | 设置
```

其中“就医模式”使用高识别度按钮，但不使用危险红色，以免制造焦虑。

# 5. 左侧导航区

左侧区域继承 3DCellForge 的“当前对象固定、历史对象折叠、任务队列独立”的组织方式。原项目将激活模型、历史资产和生成任务统一放在左侧上下文中。

BabyForge 左栏包含四个模块。

## 5.1 当前宝宝卡片

```text
┌──────────────────────┐
│ [头像] 小舟          │
│ 出生第 6 天          │
│ 新生儿早期           │
│ 足月 · 男宝          │
└──────────────────────┘
```

点击后打开宝宝档案抽屉：

- 出生日期；
- 出生孕周；
- 出生体重；
- 当前喂养方式；
- 特殊健康情况；
- 所在地区；
- 主要照护人。

------

## 5.2 阶段时间轴

```text
宝宝成长阶段
● 0–7 天      当前
○ 8–28 天     即将进入
○ 1–3 月
○ 4–6 月
○ 7–9 月
○ 10–12 月
○ 13–18 月
○ 19–24 月
○ 25–36 月
```

交互规则：

- 当前阶段固定在顶部；
- 未来阶段默认折叠；
- 点击历史阶段可回看；
- 点击未来阶段进入“提前准备”模式；
- 当前阶段切换时，中央 3D 模型和右栏内容同步更新。

------

## 5.3 当前关注队列

对应 3DCellForge 的 Generation Queue。

```text
当前关注事项  3

● 黄疸观察
  今日待记录

● 新生儿访视
  3 天后

● 疫苗记录
  待补充信息
```

状态类型：

- 待处理；
- 观察中；
- 已完成；
- 已延期；
- 需要咨询医生；
- 高优先级提醒。

这里不得自动显示“异常”或“危险”标签，除非命中了经过医学审核的确定性规则。

------

## 5.4 最近查看

记录最近进入过的：

- 疾病专题；
- 护理指南；
- 发育动画；
- 就医摘要；
- 用户收藏内容。

默认折叠，避免左栏信息过载。

# 6. 中央 3D 状态舞台

中央舞台支持四种模式。

```text
Stage Overview     阶段总览
Development Focus  发育动作
Disease Anatomy    疾病结构
Doctor Summary     就医说明
```

------

## 6.1 阶段总览模式

展示当前阶段宝宝的典型状态，而不是展示用户宝宝的医学结论。

### 新生儿示例

3D 场景包括：

- 新生儿自然蜷曲姿势；
- 轻微呼吸起伏；
- 偶发手脚活动；
- 睡眠和清醒状态切换；
- 吮吸动作演示；
- 惊跳反射教育动画。

画面叠层：

```text
新生儿早期 · 出生第 6 天

本阶段主要特点
• 大部分时间处于睡眠
• 主要通过哭声表达需求
• 喂养和排泄是重要观察指标
```

顶部角标必须显示：

```text
阶段教育示意 · 不代表宝宝实际检查结果
```

------

## 6.2 发育动作模式

用户从右栏选择一个能力，例如“抬头”，中央切换为动作演示。

```text
动作：俯卧抬头
适用阶段：1–3 月
```

播放方式：

1. 展示准备姿势；
2. 缓慢演示动作；
3. 高亮主要运动部位；
4. 展示家长可以怎样陪伴；
5. 展示不应强迫宝宝完成的动作。

可控制：

- 播放；
- 暂停；
- 0.5 倍速；
- 重播；
- 切换视角；
- 查看动作说明。

不能以动作动画作为判断发育正常与否的自动诊断工具。

------

## 6.3 疾病结构模式

中央舞台按照五步解释疾病：

```text
正常结构
   ↓
病变位置
   ↓
发生机制
   ↓
外在表现
   ↓
危险信号
```

例如中耳炎：

1. 展示头部整体模型；
2. 镜头进入耳部；
3. 高亮中耳位置；
4. 演示积液或炎症；
5. 标注宝宝可能出现的表现；
6. 展示何时需要就医。

疾病模型默认采用教育级简化表现，不展示血腥、恐怖或过度真实的病变视觉。

------

## 6.4 就医说明模式

中央舞台不再播放复杂动画，而是进入简洁展示状态：

- 宝宝基础信息；
- 当前问题；
- 症状持续时间；
- 受影响部位；
- 最近记录；
- 家长最担心的情况。

可将中央模型旋转到相关部位，并由家长手动标记：

```text
疼痛或问题可能位于：
[头部] [耳部] [口腔] [胸部] [腹部] [皮肤] [其他]
```

这些标记属于家长主观描述，不能转换成系统诊断。

# 11. 2D/3D 资源体系

## 11.1 统一身体坐标体系

所有疾病和阶段内容共享同一套身体结构 ID：

```text
body
├── head
│   ├── brain
│   ├── eye
│   ├── ear
│   ├── nose
│   └── mouth
├── neck
├── chest
│   ├── airway
│   ├── bronchus
│   ├── lung
│   └── heart
├── abdomen
│   ├── stomach
│   ├── intestine
│   ├── liver
│   └── urinary
├── skin
└── limbs
```

疾病数据只需要声明：

```json
{
  "highlightedNodes": [
    "head.ear.middle-ear"
  ]
}
```

中央模型即可自动聚焦和高亮。

------

## 11.2 2D 资源类型

每个重点疾病至少需要：

1. 身体位置图；
2. 局部解剖图；
3. 发生机制图；
4. 症状观察图；
5. 就医红旗图。

------

## 11.3 3D 资源类型

第一阶段不必为每种疾病创建独立完整模型。

采用：

```text
一个基础宝宝模型
+ 多套器官模型
+ 部位高亮材质
+ 疾病动画参数
+ 局部特效
```

例如湿疹不需要生成新宝宝模型，只需要：

- 聚焦皮肤区域；
- 应用红斑材质；
- 展示皮肤屏障分层；
- 演示水分流失与炎症；
- 切回正常皮肤进行对比。

# 12. 动画系统设计

## 12.1 动画分层

### 第一层：基础生命状态

所有阶段共享：

- 呼吸；
- 眨眼；
- 手脚轻微活动；
- 睡眠姿态；
- 视线变化。

### 第二层：阶段动作

按照阶段加载：

- 吮吸；
- 趴卧抬头；
- 翻身；
- 独坐；
- 爬行；
- 扶站；
- 行走；
- 跑跳。

### 第三层：疾病机制

按照专题加载：

- 部位高亮；
- 镜头路径；
- 解剖层展开；
- 炎症或积液示意；
- 正常与疾病切换；
- 症状位置映射。

------

# 13. 对比模式

BabyForge 应保留 3DCellForge 的对象对比思想。

原项目包含对象对比、参考模型和质量检查面板。BabyForge 将其转化为认知对比，而不是健康评分。

## 13.1 阶段对比

```text
2 月龄                4 月龄
头部控制较弱           抬头更加稳定
抓握以反射为主         主动抓握增加
互动时间较短           主动互动增多
```

必须提示个体差异，不能作为刚性达标表。

## 13.2 正常与疾病对比

例如：

```text
正常中耳              中耳炎示意
空气充足              可能出现积液
结构清晰              炎症区域高亮
```

## 13.3 相似问题对比

例如：

```text
湿疹 | 热疹 | 尿布疹
```

对比维度：

- 常见位置；
- 外观特点；
- 常见诱因；
- 是否瘙痒；
- 家长应观察什么；
- 哪些情况需要医生判断。

不直接给出“你的宝宝属于哪一种”的诊断结论。

# 15. 视觉设计

## 15.1 视觉原则

- 专业但不冰冷；
- 柔和但不幼稚；
- 使用医疗教育图形语言；
- 避免卡通化器官和恐怖病理图；
- 避免用红色制造焦虑；
- 危险提示仅在必要位置使用。

## 15.2 建议色彩

```text
主色：深蓝灰
辅助色：青绿色
成长状态：蓝绿色
待办提醒：柔和橙色
医疗关注：低饱和红褐色
背景：浅灰白
卡片：白色或轻微蓝灰
```

## 15.3 3D 模型风格

建议采用：

- 半写实教育模型；
- 柔和材质；
- 低刺激面部特征；
- 适度简化器官；
- 可拆解结构；
- 不追求医学影视级病理表现。

# 18. MVP 关键验收标准

## 工作台

- 用户进入后 5 秒内能理解宝宝当前阶段；
- 首页只突出最多 3 项优先事项；
- 阶段切换后，中央舞台与右栏同步刷新；
- 3D 加载失败时自动降级为 2D 图；
- 低性能设备可以关闭动画。

## 疾病页

- 每个专题均展示身体位置；
- 每个专题均有正常结构和疾病结构对比；
- 所有原因表述为常见原因、诱因或机制；
- 红旗信号必须来自审核规则；
- 家长原始观察与系统解释明确区分；
- 所有医学内容展示来源、版本和审核日期。

## 安全

- AI 不生成未经审核的急救标准；
- AI 不基于 2D/3D 选择结果诊断疾病；
- 疾病页面不提供处方药推荐；
- 用户可以一键进入就医摘要；
- 数据支持完整删除和家庭成员权限管理。

# 19. 第一版核心用户路径

```text
首次进入
→ 创建宝宝档案
→ 根据出生日期进入当前阶段
→ 中央展示当前阶段宝宝动画
→ 右侧展示今日重点
→ 用户发现宝宝皮肤发黄
→ 点击“我担心宝宝”
→ 选择“皮肤或眼白发黄”
→ 进入黄疸专题
→ 查看身体位置和机制动画
→ 记录出现时间、吃奶、精神和尿便
→ 系统根据审核规则提示观察或就医
→ 生成就医摘要
```

这个路径体现 BabyForge 的完整闭环：

> 看懂当前状态 → 找到具体问题 → 理解发生机制 → 记录关键事实 → 得到下一步行动。

## 最终产品原则

BabyForge 的中央 3D 舞台负责让家长“看懂”，右侧知识检查器负责让家长“理解”，左侧关注队列负责让家长“行动”。

产品不应把所有育儿知识都做成 3D。只有空间结构、动作发展和疾病机制适合 3D；判断标准、护理步骤、危险信号和操作指导通常更适合清晰的 2D 图文。

因此第一版应坚持：

> **3D 用于解释，2D 用于指导，规则用于决策，医生负责诊断。**
